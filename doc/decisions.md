# Architectural Decisions

This maintained document summarizes the Accepted ADRs governing this
repository. The complete ADR texts remain authoritative; applicable
released standards and explicit local policies also govern changes.

## ADR-001: Adopt Shared Coding Standards

The repository adopts a complete versioned standards snapshot under
`doc/standards/`. The root `.codingstandardrc` records the current
release and archive digest. Applicable standards govern unless an
Accepted local ADR or explicit policy refines them, and managed
standards are not locally edited.

See [ADR-001](adr/ADR-001-adopt-shared-coding-standards.md).

## ADR-002: Define Runtime and Testing Contract

The uploader's public Bash execution and CLI behavior remain within
the documented runtime contract. Tests use observable behavior with
controlled external boundaries instead of relying on live external
services for routine CI. Future changes require explicit verification
of return status, data flow, and compatibility.

See [ADR-002](adr/ADR-002-define-runtime-and-testing-contract.md).

## ADR-003: Treat Configuration Files as Trusted Executable Input

Configuration files are intentionally sourced as executable Bash code
and must not be represented as inert data. Callers must not source
untrusted configuration content. The tool preserves documented
precedence and fails conservatively for explicitly requested
configuration files that cannot be read.

See [ADR-003](adr/ADR-003-trusted-executable-configuration.md).

## ADR-004: Govern Release Classification Through Reviewed Conventional Titles

Pull-request and merge titles convey reviewed Conventional Commit
release significance. Issue labels or other untrusted metadata do
not independently authorize semantic version changes. Reviewers
must keep the final merged title consistent with the scope of the PR.

See [ADR-004](adr/ADR-004-reviewed-conventional-release-classification.md).

## ADR-005: Adopt bashdeps-Managed Embedded bashlog

Repository dependencies are pinned and synchronized through bashdeps,
with generated vendor files excluded from source control. The runtime
embeds bashlog in a standalone uploader artifact instead of depending
on a runtime vendor tree. The root compatibility path remains a
generated product whose correctness is checked during CI.

See [ADR-005](adr/ADR-005-adopt-bashdeps-managed-embedded-bashlog.md).

## ADR-006: Use adrctl to Maintain the ADR Inventory

The repository maintains human-authored ADR summaries above an explicit
marker in `doc/adr/README.md`. The exhaustive inventory beneath that
marker is generated by pinned adrctl and verified for idempotence in CI.
Contributors should update the curated section and regenerate the
inventory rather than edit generated output independently.

See [ADR-006](adr/ADR-006-use-adrctl-to-maintain-adr-inventory.md).

## ADR-007: Generate Bash Reference Documentation and Publish to Pages

Maintained Bash source is documented and validated using a pinned
bash-doxygen dependency. Generated Doxygen HTML remains ignored
derivative state, while a least-privilege Pages workflow rebuilds
reference documentation from trusted source. Documentation tooling
does not change the uploader's runtime or distribution interface.

See [ADR-007](adr/ADR-007-generate-bash-reference-documentation-and-publish-pages.md).

## ADR-008: Adopt Three-Flavor Distribution Artifacts

Builds produce development, ordinary, and minified standalone Bash
artifacts with SHA-256 companions. The historical root uploader path
remains a generated compatibility artifact corresponding to the
ordinary build. Validation tests the exact candidate distribution
bytes before the separately authorized release job publishes them.

See [ADR-008](adr/ADR-008-adopt-three-flavor-distribution-artifacts.md).

## ADR-009: Consolidate GitHub Actions Dependabot Version Updates

Routine GitHub Actions version updates remain weekly with a seven-day
cooldown, grouping eligible major, minor, and patch releases. Security
updates remain separate, and any group containing a major version
stays outside the existing non-major-only automatic-merge path.
This maintenance policy does not alter executable configuration,
DefectDojo API behavior, or published release contracts.

See [ADR-009](adr/ADR-009-consolidate-github-actions-dependabot-maintenance.md).
